## 1. Кто мы и что делаем

- **Команда:** The Catalyst (один участник — Руслан Шарафутдинов, студент 3 курса химической технологии, ЗКАТУ им. Жангир хана, Уральск).
- **Событие:** NASA International Space Apps Challenge 2026, локальное событие Уральск, 14–15 ноября 2026.
- **Челлендж:** *Flame in Freefall: AI-Powered Fire Safety Insights from Microgravity Combustion Data*.
- **Суть челленджа:** результаты экспериментов по горению в невесомости (в основном с МКС) публикуются в базе NASA Physical Sciences Informatics (PSI), но данных много, их трудно найти, сравнить и интерпретировать. Нужно сделать интерактивный ИИ-дашборд, который суммирует, ранжирует и интерпретирует эти результаты и выдаёт выводы по пожарной безопасности для пилотируемых полётов.
- **Наш подход (идея Руслана):** physics-informed ML в стиле PRISM:
  1. физические законы горения →
  2. поправка/учёт микрогравитации →
  3. калибровка на экспериментальных данных NASA →
  4. ML учит только то, что теория не объясняет, и показывает свою неопределённость →
  5. дашборд с ранжированными, проверяемыми выводами (предотвращение / обнаружение / тушение).

## 4. Научная честность (обязательно для критерия Validity)

- **Утечка данных запрещена:** признаки модели — только величины, известные **до зажигания** (топливо, состав атмосферы, давление, размер/геометрия образца, поток и т.п.). Величины, измеренные после теста (время горения, диаметр затухания и т.п.), — только цели или анализ, никогда не признаки.
- **Кросс-валидация по группам:** повторы одного режима (серии тестов) никогда не попадают одновременно в train и test.
- Всегда сравнивай с **базовыми моделями**: «среднее», «только физика», «только ML», «гибрид».
- Делай **тест на экстраполяцию:** выкидываешь из обучения целый класс условий (разбавитель, топливо, диапазон давления) и проверяешь прогноз.
- Каждый вывод в интерфейсе помечен типом доказательства: `NASA data` / `model` / `physics theory` / `NASA literature` / `NASA history` (Apollo 1, Apollo 13, «Мир») / `NASA spinoff`, плюс число тестов, на которых он основан (для истории и спинофов — 0, зато ссылка на страницу).
- Прогноз вне диапазона экспериментов помечается как **экстраполяция**.
- Провалы модели не прячем — описываем в `docs/VALIDATION.md` и в интерфейсе.
- Аномалии в исходных данных (опечатки, нули, пропуски) не исправляем молча: помечаем флагом, объясняем, спрашиваем Руслана.
- Единицы: внутри кода — СИ; в интерфейсе — привычные для отрасли (мм²/с, атм, мм рт. ст., psia) с явной подписью.

Принципы:
- Слои независимы: `data → physics → models → validation → insights → app`. Интерфейс не считает физику сам, а вызывает пакет.
- Всё воспроизводимо из `data/raw` одной командой, с фиксированным seed.
- Тяжёлые вычисления кешируются; приложение стартует < 30 с.
- Каждый модуль имеет docstring с назначением, входами/выходами, единицами и ссылками на `docs/PHYSICS.md`.

## 6. Система документации (ведётся непрерывно, а не в конце)

   - Options: A) … B) … C) …

3. Обнови профильный документ этапа (DATA_*, PHYSICS, MODEL_CARD, VALIDATION, INSIGHTS, UI_SPEC).
4. Если использовался ИИ для генерации кода/текста/данных/картинок — отметка в `docs/AI_USAGE.md`.
5. Git-коммит: `<stage>: <что сделано>` (например, `data: parse FLEX table IX`). Мелкие коммиты, после каждого рабочего шага. В конце этапа — тег `stage-N`.
6. Если число попало в интерфейс или README — в документе должно быть видно, откуда оно.

## 7. Требования к сабмиту Space Apps (держать в голове с первого этапа)

Обязательные поля формы (всё на английском): Project Name; High-Level Project Summary; Link to Project Demo; Link to Final Project (публично доступная); Detailed Project Description; NASA Data (что и как использовали); Space Agency Partner & Other Data (все данные, ресурсы и инструменты); Use of Artificial Intelligence; подтверждение Terms and Conditions и оригинальности работы.

Демо — на выбор: **видео до 30 секунд с английскими субтитрами** или **до 7 слайдов** (включая титульный), на внешнем хостинге без пароля и регистрации. Превышение лимитов = нет допуска к глобальному судейству.

ИИ разрешён, но надо явно указать, где и как он использован; картинки/видео, созданные ИИ, — с видимой пометкой; ИИ-контент не должен содержать или изменять брендинг NASA.

Критерии судейства: **Impact, Creativity, Validity, Relevance, Presentation.**

Дедлайн: проверь точное время в Project Submission Guide 2026 (ориентир — до 23:59 воскресенья 15 ноября по времени локального события). «Submit for Judging» нужно нажать до дедлайна; сабмит окончательный.
